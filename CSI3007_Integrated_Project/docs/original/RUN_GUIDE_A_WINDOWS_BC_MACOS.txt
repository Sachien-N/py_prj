This guide explains how to run the three applications on three different
computers on the same local network (LAN) or the same private VPN:

  Windows computer  -> Person A: Smart Expense Categorization and Budget Manager
  Mac computer 1    -> Person B: Smart Subscription Manager
  Mac computer 2    -> Person C: Smart Home Electricity Monitoring and
                                  TNEB Bill Verification System

Each person runs only their own folder. Each folder contains its own FastAPI
backend, Streamlit dashboard, SQLite database, configuration, tests and README.
The applications communicate only through authenticated JSON over HTTP.

Important:
  - Do NOT use run_all.py for this three-computer arrangement. run_all.py is a
    single-machine convenience launcher.
  - Do NOT share database files between computers.
  - Do NOT expose these development services directly to the public Internet.
  - Run all three computers on the same trusted LAN or private VPN.
  - A and B/C must be able to reach each other over TCP; the standard local
    ports are used below.

0. QUICK TOPOLOGY
================================================================================

  +------------------------------------------------------+
  | WINDOWS - PERSON A                                   |
  | API:        http://<WINDOWS_A_IP>:8001               |
  | Dashboard:  http://127.0.0.1:8501 (on the PC)        |
  | Database:   person_a_sachien_n_23MID0255/data/person_a.db |
  +------------------------------------------------------+
        ^                                  ^
        | B push (X-API-Key)               | C push (X-API-Key)
        |                                  |
  +-----------------------------+    +-----------------------------+
  | MAC 1 - PERSON B            |    | MAC 2 - PERSON C            |
  | API: http://<MAC_B_IP>:8002 |    | API: http://<MAC_C_IP>:8003 |
  | UI:  http://127.0.0.1:8502  |    | UI:  http://127.0.0.1:8503  |
  | DB:  data/person_b.db       |    | DB:  data/person_c.db       |
  +-----------------------------+    +-----------------------------+

Primary data flow:
  Person B --POST /integrations/subscriptions/sync--> Person A
  Person C --POST /integrations/electricity/sync----> Person A

Optional reverse flow:
  Person A can pull from Person B/C if their APIs are reachable and the A .env
  URLs are configured. The normal/push flow is enough for the demonstration.

Before starting, write down the actual IP addresses:

  WINDOWS_A_IP = __________________  (example 192.168.1.50)
  MAC_B_IP     = __________________  (example 192.168.1.61)
  MAC_C_IP     = __________________  (example 192.168.1.62)

Use IP addresses in the .env files, NOT "localhost", when one computer connects
to another computer. "localhost" always means the same machine.

Replace every <PLACEHOLDER> in this guide, including the angle brackets, with
your real IP address, key, or path.

Pinned packages include FastAPI, Uvicorn, SQLAlchemy, Pydantic, Streamlit,
Requests, pandas, NumPy, Plotly, python-dotenv, python-multipart and pytest.

4.5 Create the environment file

  Copy-Item .env.example .env
  notepad .env

Replace its contents with the following. Replace the example IPs and keys.

  DATABASE_URL=sqlite:///./data/person_a.db
  API_HOST=0.0.0.0
  API_PORT=8001
  API_BASE_URL=http://127.0.0.1:8001
  PERSON_B_API_URL=http://<MAC_B_IP>:8002
  PERSON_C_API_URL=http://<MAC_C_IP>:8003
  PERSON_B_SYNC_API_KEY=<PASTE_B_KEY_HERE>
  PERSON_C_SYNC_API_KEY=<PASTE_C_KEY_HERE>
  INTEGRATION_TIMEOUT_SECONDS=5
  INTEGRATION_RETRIES=2
  CORS_ORIGINS=http://127.0.0.1:8501,http://localhost:8501

Notes:
  - API_BASE_URL stays 127.0.0.1 because the Windows dashboard talks to the
    Person A API on the same Windows computer.
  - PERSON_B_API_URL and PERSON_C_API_URL use the Mac IP addresses; they are
    needed only for the optional A-pull buttons.
  - No spaces around "=".
  - Do not wrap values in quotes.

4.6 Allow Person A API through Windows Firewall

Open PowerShell as Administrator and run:

  New-NetFirewallRule -DisplayName "Person A API 8001" -Direction Inbound -Protocol TCP -LocalPort 8001 -Action Allow -RemoteAddress LocalSubnet

"LocalSubnet" limits access to the local network. If this rule already exists,
skip it. Do not create a public Internet port-forward for port 8001.

If Windows asks whether the network is Public or Private, choose Private for a
trusted home/college LAN.

4.6b If TCP port 8001 is already used by an unrelated application

Do not kill a process you do not recognize. Choose another port for Person A,
for example 8011. Then you must change ALL of the following consistently:

  - Start the A API with: --port 8011
  - Open the firewall for TCP 8011 instead of 8001.
  - In Person A .env: API_BASE_URL=http://127.0.0.1:8011
  - In Person B .env: PERSON_A_API_URL=http://<WINDOWS_A_IP>:8011
  - In Person C .env: PERSON_A_API_URL=http://<WINDOWS_A_IP>:8011
  - A API docs: http://127.0.0.1:8011/docs

The same idea applies if B's 8002 or C's 8003 is taken: choose another port and
update the corresponding URL in Person A's .env (for optional pulls) and in the
affected project's API_BASE_URL.

4.7 Find the Windows computer's LAN IP address

  ipconfig

Under the active Wi-Fi or Ethernet adapter, note the "IPv4 Address",
for example 192.168.1.50. This is WINDOWS_A_IP.

Test locally:

  Invoke-RestMethod http://127.0.0.1:8001/health

(That works after the API is started in the next step.)

You should see "Uvicorn running on http://0.0.0.0:8001".

8. RUN THE TWO INTEGRATIONS
================================================================================

8.1 Person B -> Person A

On Mac B, after adding at least one active subscription:
  1. Open the Person B dashboard: http://127.0.0.1:8502
  2. Go to "Integrations".
  3. Click "Sync now" for the current billing period.
  4. A success message should say Person A accepted the records.

Equivalent command from Mac B:

  curl -X POST "http://127.0.0.1:8002/integrations/person-a/sync" \
       -H "X-API-Key: <PASTE_B_KEY_HERE>"

The B API forwards the payload to:

  POST http://<WINDOWS_A_IP>:8001/integrations/subscriptions/sync
  Header: X-API-Key: <B_KEY>

What A receives:
  - Source application: person_b
  - One record per active subscription and current period
  - Stable external IDs such as: sub:1:2026-10
  - is_estimate=true if this is the expected recurring cost
  - is_estimate=false if an actual payment was recorded for that period

8.2 Person C -> Person A

On Mac C:
  1. Open http://127.0.0.1:8503
  2. Go to "Integrations".
  3. Choose the expense period if desired.
  4. Click "Push electricity expenses to Person A".
  5. A success message should show the number of records accepted.

Equivalent command from Mac C:

  curl -X POST "http://127.0.0.1:8003/integrations/person-a/sync" \
       -H "X-API-Key: <PASTE_C_KEY_HERE>"

Optional explicit date range:

  curl -X POST "http://127.0.0.1:8003/integrations/person-a/sync?start_date=2026-04-01&end_date=2026-10-31" \
       -H "X-API-Key: <PASTE_C_KEY_HERE>"

The C API sends monthly records to:

  POST http://<WINDOWS_A_IP>:8001/integrations/electricity/sync
  Header: X-API-Key: <C_KEY>

What A receives:
  - Source application: person_c
  - Stable external IDs such as: electricity:2026-09
  - Actual bill amount where a bill was recorded
  - Otherwise a clearly marked configured-tariff estimate
  - Data coverage percentage and units

8.3 Verify Person A imports

On Windows A:
  1. Open http://127.0.0.1:8501.
  2. Open "Integrations" and click "Refresh"/"Check live connectivity".
  3. Confirm Person B and Person C show success and a last-success timestamp.
  4. Open "Expenses" and filter Source = person_b, then person_c.
  5. Confirm that imported rows show the correct source and estimated flag.
  6. Imported rows are read-only in Person A; correct them at their source.

Command-line checks on Windows A:

  Invoke-RestMethod "http://127.0.0.1:8001/expenses?source_app=person_b"
  Invoke-RestMethod "http://127.0.0.1:8001/expenses?source_app=person_c"
  Invoke-RestMethod "http://127.0.0.1:8001/integrations/status"

8.4 Test duplicate prevention

Click "Sync now" twice in Person B or "Push electricity expenses" twice in
Person C. Person A must update the existing external records, not create
duplicate rows.

The deduplication key is:
  UNIQUE(source_app, external_id)

Examples:
  person_b + sub:1:2026-10
  person_c + electricity:2026-09

8.5 Test the offline behaviour

  1. Stop Person A's API with Ctrl+C on Windows.
  2. In Person B/C, click sync.
  3. The sender should report HTTP 503/failure, and its local subscription or
     electricity data must remain intact.
  4. Restart Person A's API.
  5. Click sync again. It should succeed.

No placeholder or fabricated external data is written when a service is
unavailable.

8.6 Optional: Person A pulls from B/C

The primary flow is B/C push. If you want the A "Sync subscriptions" and
"Sync electricity" buttons to pull from the Macs:
  - B/C APIs must be started with --host 0.0.0.0.
  - A's .env PERSON_B_API_URL / PERSON_C_API_URL must contain the Mac IPs.
  - macOS firewall must allow incoming TCP 8002/8003.
  - A's PERSON_B_SYNC_API_KEY / PERSON_C_SYNC_API_KEY must match B/C keys.

If those conditions are not met, A shows a safe failure message; use the push
buttons on B and C instead.

  Windows:
    Remove-Item .\data\person_a.db

================================================================================
11. TROUBLESHOOTING
================================================================================

Problem: "Connection refused" from another computer.
Fix:
  - Is the API running?
  - Was it started with --host 0.0.0.0, not --host 127.0.0.1?
  - Is the correct IP address in .env?
  - Is the Windows firewall rule allowing TCP 8001?
  - Are both computers on the same LAN/VPN?

Problem: curl hangs/times out.
Fix:
  - Test localhost first on the server computer.
  - Check firewall and Wi-Fi isolation ("client isolation" on some routers).
  - Ensure no VPN route conflict.
  - Ping the target IP.

Problem: HTTP 401 from an integration.
Fix:
  - The X-API-Key value does not match.
  - Person A's PERSON_B_SYNC_API_KEY must equal Person B's
    PERSON_A_SYNC_API_KEY.
  - Person A's PERSON_C_SYNC_API_KEY must equal Person C's
    PERSON_A_SYNC_API_KEY.
  - Restart the API after editing .env.

Problem: HTTP 503.
Fix:
  - The destination API is offline or timed out.
  - Start Person A and retry.
  - Local data is preserved; no need to re-enter it.

Problem: Person A can push from B/C but the A "pull" buttons fail.
Fix:
  - That is expected when B/C APIs are local-only.
  - Either use B/C push (recommended), or bind B/C APIs to 0.0.0.0 and allow
    ports 8002/8003 through the Mac firewall.

Problem: Dashboard says API offline.
Fix:
  - Start that project's API.
  - Confirm API_BASE_URL in that project's .env is http://127.0.0.1:<port>.
  - Refresh the browser.

Problem: Person C comparison says no usable readings.
Fix:
  - Add at least two readings with an interval no longer than
    MAX_READING_GAP_HOURS (default 4).
  - Check the reading times are within the billing period.
  - Data coverage is shown; gaps are not filled with invented energy.

Problem: Person C says no active tariff.
Fix:
  - Add/activate a tariff configuration effective on the bill's end date.
  - Verify the tariff's slabs and effective dates.
  - Remember that the bundled tariff is only an illustrative demo.

Problem: macOS blocks Python.
Fix:
  - System Settings > Network > Firewall > Options > allow Python.
  - If you do not need A-pull, you can keep B/C APIs bound to 127.0.0.1 and use
    push only.

Problem: Port already in use.
  Windows:
    Get-NetTCPConnection -LocalPort 8001
    Stop the owning process only if you know it is the old API.
  macOS:
    lsof -nP -iTCP:8002 -sTCP:LISTEN
    Stop the owning process only if you know it is the old API.

Problem: PowerShell cannot activate .venv.
  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Problem: Python command not found on Mac.
  Use python3, or install Python 3.11+ and use python3 -m venv .venv.

Problem: Wrong database state.
  Stop the API, back up or delete the relevant data/*.db file, and restart.
  Never point two projects at the same SQLite file.

12. SECURITY RULES FOR THIS DEPLOYMENT
================================================================================

1. Use only a trusted LAN or a private VPN. Do not forward ports 8001/8002/8003
   from your Internet router.
2. Use two strong, different integration keys. The sample "dev-..." keys in
   .env.example are for local development only.
3. Keep .env files local. Never commit them.
4. The integration sync endpoints are authenticated. Core CRUD/read APIs are not
   user-authenticated, so do not expose the APIs to the public Internet.
5. There is no user login in the dashboards. This is a single-user academic
   project, not a multi-tenant service.
6. Person C's tariff data must be verified independently against an official
   TNEB/TANGEDCO tariff order before any real bill decision.
7. Person C never asserts that a utility bill is incorrect. The analysis reports
   observed facts, potential explanations and missing data only.
8. Person B never claims an actual payment was processed automatically. Actual
   payments are manually recorded facts.

  distributed three-computer deployment.
